## 0. Instructions for Humans (AIs: skip this section and start executing from Chapter 1)

**What this is**: after a B6 analysis finishes, the conclusions are scattered across thousands of words of execution report that humans have no time to read. This prompt makes the AI compress the analysis results into a **human-readable edition**: page 2 answers the five questions humans care about most, up front; details follow; appendices mop up.

**How to use**:
1. Send an AI the full text of this file + one line, "Project name: ____" + project material (README, development notes, data — the more the better). **This single file is all you need** — the methodology concepts are inlined in §1.0; no need to attach the MDPAF B6 source document itself;
2. The AI first completes the analysis under the §1.0 B6 standard, then typesets the report;
3. The AI generates HTML and converts it to PDF, with the filename `ProjectName_MultiDimensional_Analysis_HumanReadable_YYYYMMDDHHMM`.

**Naming rules (hard)**: the report filename and its content are **entirely in Simplified Chinese** (Arabic numerals and underscores excepted) when the report is written for a Chinese-reading audience; the timestamp is taken live with the `date` command, in the format `YYYYMMDDHHMM` (12 consecutive digits), **never estimated, never hardcoded**. Every regeneration produces a new filename; old files are never overwritten and are kept for reference.

## 1. Prompt Body (the following is handed to the AI verbatim)

You have just completed (or are about to complete) a full analysis of a project using the "Multi-dimensional Analysis Method" (MDPAF). Now organize the analysis results into a **human-readable report** and output it as a PDF.

### 1.0 The Methodology (inlined from the full thought section of MDPAF B6; the source file exists independently — where this section conflicts with the source, the source prevails)

#### 1.0.1 What this method is

MDPAF is a method of thought for gating, analyzing, refining, and extending an object (product / project / work / feature / idea).

**The whole method in one sentence**: use "has anyone paid a price" to test truth (gatekeeping twice; the Fine Gate expanded into the full Seven Pain Questions — real, scale, solution, will, degree, coping — closing with the Timing Question "why now"), place the idea back into the long chain of the user's world to position it (Map to build coordinates → Re-slice to settle scope), then **mount value judgments per scope** (gaps, incumbents, position, payment — each hung on its proper layer), close with "evidenced conclusions + ranked, priced actions," and grow four ways along the chain while every candidate is re-forged and re-examined — throughout, trust cost, distrust slogans, and be ready to redraw the map at any time.

**Why "multi-dimensional"**: more than one ruler (multiple sets of value judgments) and more than one layer of scope (macro/micro layering) — layer and ruler combined give the full picture.

#### 1.0.2 The Four Verbs

The body of the methodology is four verbs: **Gate → Analyze → Refine → Extend**. They form a loop: new objects generated by Extend go back through Gate again.

Unified statement: all four verbs are "actions taken on scope" —

| Verb | What it does to scope |
|---|---|
| **Gate** | Gatekeep the coarsest scope (the block the idea claims to cover) |
| **Analyze** | Map to build coordinates → Re-slice to settle scope → mount judgments per scope |
| **Refine** | Close actions over all known scope |
| **Extend** | Generate new scope candidates, throw them back through Gate |

**1. Gate — "Is it worth it?" (first pass of gatekeeping: the Coarse Gate)**

Before investing any analysis resources, probe authenticity with one ultra-cheap question:

> **Has anyone already paid a price for this?** (Time, money, hassle — all count.)

- Only people who have felt the pain will pay, spend time, or put up with hassle. If nobody has ever hurt over it, however exquisite the analysis, you are decorating a hallucination.
- This is the method's goalkeeper: verdict "not real" → terminate on the spot, cost zero.
- Verbally wanting it, or politely complimenting it, does not count as paying a price — only actually incurred cost behavior counts.
- This verb performs the **Coarse Gate** (first pass): its object is the pain block the initiator **claims**, aiming to filter obvious hallucinations at zero cost. After Mapping and Re-slicing the scope may shift; after the shift the **Fine Gate** (second pass, see Analyze step 2) must be run again — since B4, the Fine Gate is the full **Seven Pain Questions**.

**2. Analyze — "Map → Re-slice → Measure"**

Analysis is not a parade of rulers taking the stage in turn. **Block-slicing defines the scope; rulers judge value on the scope** — so the question "when does which ruler enter" does not exist; only "on which scope, which set of value judgments" exists. Three steps:

**Step one: Map — build the coordinate system (position within the user's world)**
- **The idea is not the top of the scope.** Your project / idea is almost always a block in the middle of a long chain — between macro and micro, embedded in one big chain of the user's world. Taking "the idea as a whole" as the coordinate origin means drawing the map with the initiator's own boundaries — a covert form of "drawing the denominator wrong": the denominator says "user perspective," but the drawing is of yourself.
- Operation: put the idea into its long chain (the user's complete process of getting the thing done), **scan forward, backward, and sideways**, and draw the full shape of the chain — the blocks before you (what the user does before reaching you), the blocks after you (what they do afterward), the parallel blocks (branches running at the same time). This step draws only — no judging, no selecting.
- **Mapping stop point (task anchor)**: extend until "the nearest user-task closed loop within which the object's position is clear" (a meal finished, a trip completed — the completion signal of the user's task). **Anchor layering, reused**: phase anchors (dishes served, chopsticks down) slice blocks; task anchors bound the long chain — anchors are the universal scale of the whole scope axis; do not trace upward indefinitely.

**Step two: Re-slice — settle the scope (Side-by-Side Reveal + Coverage Correction + Fine Gate)**
- Under the long-chain coordinate system, re-examine the slicing: which blocks of the chain does your idea actually cover? Slicing follows the **user's sense of phases** and is settled with the **Merge–Split Double Check** (trades neighbors freely and exists stably in other valid combinations = an independent block; adjacent blocks that fall apart if any segment is swapped = strongly coupled = merge into one big block, split block-by-block only inside the sub-chain — both checks presuppose the declared closed-loop goal; these are tendency criteria, with gray areas returning to the stop-splitting rule).
- **Side-by-Side Reveal (anti-self-persuasion)**: write out side by side "the blocks you claimed to cover before Mapping" and "the blocks you actually cover after Re-slicing." Where they differ, all subsequent analysis must turn to the **new blocks** — the old pain descriptions may not be reused. Effort already spent drawing the chain is not a reason: sunk cost will push you to argue "it's actually still my original block"; the Reveal exists to block that move.
- **Coverage Correction**: the direction and magnitude of the scope shift is itself the first output of the analysis — it is often exactly where the product positioning should really be adjusted; record it truthfully.
- **Fine Gate (second pass, expanded since B4 into the Seven Pain Questions)**: once the scope is settled, run the seven questions over **these actually covered blocks** — ① **real**: have users paid a price for them (the original Fine Gate question); ②③ **scale**: how painful × how many people in pain (intensity × breadth = the pain ledger); ④ **solution**: does one exist (if none, ask whether it can be solved; if one exists, register the incumbents one by one); ⑤ **will**: does the user want to solve it themselves (have they taken escape actions — searched for alternatives, tried tools, spent money; you worrying on their behalf doesn't count); ⑥ **degree**: how much do existing solutions solve (percentage solved + Weight of Concession + Bonus Hard Constraint, see Incumbents in Analyze step three; the percentage has a shelf life — how long it holds under current technical capability, see Belief Three, Corollary Three); ⑦ **coping**: what happens after the pain (the Folk Workaround — the real starting line). After the seven questions, **append the Timing Question (new in B6): "Why do this now?"** — current technical capability just barely reaching it = the window just opened (the payoff moment of the Embedding Position; first-mover advantage is greatest); capability reached long ago yet nobody has done it = go back and re-examine ④ (the Graveyard) and ⑤ (will) — "nobody has done it" means either there is a reason or there are corpses; both must be asked out. Evidence cited at the Coarse Gate that belongs to old blocks, when the new blocks differ, is not inherited automatically — new evidence must be supplied. Coarse Gate + Fine Gate = gatekeeping twice: first save cost (filter hallucinations), then keep coordinates true (seven questions aimed at the new blocks).

**Step three: Measure — mount judgments per scope**

There is no "four rulers entering in turn"; what exists is **scope determines the judgment combination**:

| Scope | Value judgments mounted |
|---|---|
| **The long chain** (the coordinate system from Mapping) | Ceiling magnitude (long chain / short chain); drift signals: which blocks are growing or shrinking under technology, habits, policy |
| **The object's covered block group** (settled by Re-slicing) | Fine Gate (price-paid re-verification); entry value (how many heavy blocks, choke point or not, broken link or not); Payment Triangle (object-level roles); total-board business |
| **Core blocks** (heavy blocks and choke points; light blocks get less) | Incumbents and the Folk Workaround (who is making do on this block); the user's will (do they want it solved); weight (time / difficulty / repetition / cost / scope); satisfaction and switching cost; Weight of Concession and Bonus Hard Constraint; Payment Trigger; Opportunity Formula (block-level, below); magnified observation (sub-chains and sub-chain choke points) |
| **Candidate blocks** (generated by Extend) | Full re-forge check: candidates get no exemption — run the full "Map → Re-slice → Measure" flow |

- **Mounting density control**: heavy blocks and choke points get everything; light blocks get little — isomorphic to the stop-splitting rule: layers not asked about are not split; blocks not asked about are not mounted.
- **Opportunity Formula pushed down (block level)**: opportunity = low satisfaction with **that block's** existing solutions, and low cost for users to switch to yours. Opportunity is no longer one chain-level blanket verdict but a per-block local judgment — on the same chain, some blocks are opportunities and some are also-rans; exactly this is what a blanket "there is opportunity" conceals.

Key points of each judgment group (hung on their proper scopes):

**Gaps (object level)** — split "wants to solve / can solve / actually solves" into three segments: the "want vs can" gap = a design problem; the "can vs actually" gap = a landing problem; the two diseases need different medicine; "wants to solve" is quoted verbatim; "actually solves" requires measured evidence — if absent, say so honestly.

**Incumbents (block level)** — who is already solving on this block? The Folk Workaround (the user's present make-do method) is the real competitor; satisfaction must distinguish "using it while complaining" (something tethers them — don't touch) from "complaining then leaving" (opportunity); switching cost must be decomposed (money, data migration, habits, relationships, relearning); **the user's will** (added in B4): does the user want out themselves — the criterion is escape actions (sought alternatives, tried tools, spent money); you fretting on their behalf doesn't count; **Weight of Concession** (added in B4): how the user concedes on what existing solutions fail to solve (enduring, detouring, jury-rigging, giving up) — the lighter the concession, the less the residual pain is worth; the heavier the concession, the bigger the entry point; **Bonus Hard Constraint** (added in B4): the extra benefit of "solves the original pain and, incidentally, also…" counts only if someone has paid a price **specifically** for that bonus — otherwise record it without scoring it; solutions run in two directions — if no solution exists, ask "can it be solved" (no = a science problem, not a product problem); if one exists, ask "replication difficulty" (easy = anyone can enter; very hard = a breakthrough qualification or an exit); the Graveyard is a warning, not a blue ocean; **plagiarism runs both ways**: whether others can be copied by you (replication difficulty), and whether you can be copied by others (moat) — check both sides.

**Payment (object-level triangle + block-level trigger)** — user, decision-maker, payer, named one by one; when they don't coincide, aim every action at the one who pays (the pitch is spoken to whoever buys); each block has its own pain peak; put the fee right against the trigger.

**3. Refine — "What next?"**

When the analysis is done, close into two things, under two iron rules:
1. **Conclusions may not introduce new evidence.** At closing, only facts established earlier may be used — to prevent on-the-spot storytelling and conclusions escaping the evidence.
2. **Actions must be ranked and priced.** Writing "strengthen" or "optimize" — wishes that cost nothing and cannot be accepted — is forbidden; every action must answer "which first, at what cost, what counts as done."

One counter-intuitive answer is permitted: **the best refinement is not refining.** For some objects the conclusion is "stop," and the first line of the action list is "stop investing; cost zero."

**4. Extend — "What else can grow on the chain?"**

Once the position is settled (on the coordinate system built by Mapping), scan growth candidates along the chain in four directions:

| Direction | Meaning |
|---|---|
| **Upstream** | Occupy the block ranked before you (doing distribution → go do creation) |
| **Downstream** | Occupy the block ranked after you (doing transactions → go occupy payments) |
| **Parallel** | Grow a branch sharing the same resource pool (drivers and algorithms are reusable → grow designated-driver service) |
| **Morph** | Claim no new position; reshape the chain itself: split, merge, add, delete |

Growth must pass three gates, none dispensable:
1. **Re-forge Gate**: every new candidate enjoys no exemption — return to "Gate → Analyze" and re-audit from the start (Mapping, Re-slicing, Fine Gate, block-by-block judgment, nothing less). Generating candidates costs zero, which is the easiest way to induce hallucinations.
2. **Adjacency Gate**: grow only on parcels sharing "users / capabilities / resources" with the current position. Adjacent on the chain ≠ adjacent in capability — being close is not being able.
3. **Priority Gate**: all else equal, occupy choke points first, heavy blocks next, light blocks last.

**Principle: growth supplies the boldness; analysis does the killing.**

#### 1.0.3 The Three Beliefs That Run Through Everything

Three beliefs support all four verbs. The verbs are technique; the beliefs are the soul.

**Belief One · Order is logic**

The order Gate → Analyze → Refine → Extend is not swappable: if the pain isn't real, talking competition is meaningless; if the vacancy doesn't exist, talking position is meaningless; if the position is wrong, talking revenue is meaningless. Every later question stands on the one before it passing. Every answer obtained by skipping order stands on unverified foundations. The coarseness of scope layers also lives in the order: Coarse Gate before Mapping, Fine Gate after Re-slicing, rulers after settling — answers obtained by skipping layers are equally foundationless.

**Belief Two · Cost is the only lie detector**

Slogans don't count; likes don't count; sentiment doesn't count — only "behavior that has paid a price" counts. The sharpest judgments in this method all come from here: the Folk Workaround is the real competitor (the user has already paid habits for it); "using it while complaining" is not an opportunity (their cost of enduring is lower than their cost of leaving); the payment moment is the moment the pain flares (they are most willing to pay right then); phase boundaries follow anchors, not durations (the user has paid cognition for their own segmentation); the user's will is read from escape actions, not from words (actions cost); the Weight of Concession measures costs the user is already paying; both gatekeeping passes are cost tests (has anyone paid a price). Every doubt in the analysis comes down, at the end, to one question: **what has anyone spent on it?**

**Belief Three · Maps expire**

Blocks on the chain grow and shrink under technology, habits, and policy — a block may be flattened by a new tool, its value not vanishing but migrating to neighboring blocks (when payments were flattened, value flowed to data and credit). Under the recursive structure, drift can happen at any layer: an upper block flattens, and the sub-chains reorganize; block replacement is itself an aggregation surface of drift (when "cooking at home" is replaced by "ordering in," the structural anchor "eating" is unchanged). **Drift also happens to solutions (added in B5)**: new solutions pop up as technical capability rises, and old solutions strengthen as it rises — "no solution" may just mean the technology hasn't arrived yet (a question of time, not of science), and the residual space of "seventy percent solved" may be eaten directly by a rival's technical progress; the criterion is restricted to **the natural extension of existing technology at its current rate of improvement** — no science-fiction leaps are predicted. Three corollaries: ① **every conclusion has a shelf life** — today's choke point may be flattened tomorrow; assessment conclusions need periodic re-verification; ② **drift is a signal** — "which block is growing" is itself the hint of the next growth direction; before Extend scans, first look at where the chain is rising; ③ **opportunities have a shelf life (added in B5)** — the residual pain space measured by the Fine Gate and the Incumbents analysis must be labeled "how long it holds under current technical capability, and when it can be replicated"; an opportunity judgment without a re-verification date counts as unfinished.

#### 1.0.4 The Core Model · The Behavior Chain

The position coordinate system of this method is the **Behavior Chain** (the author's original concept): the user-perspective **minimal complete closed loop** (from first impulse to "done") is joined by multiple **behavior blocks**. Construction rules: **phase-sense slicing** (boundaries follow the user's psychological segmentation; physical anchors locate boundaries; physical quantities are measurements after slicing, not the basis for slicing); **recursive structure** (there is no absolute macro or micro; magnify a block and it becomes a sub-chain); **layer declaration** (denominator layering; declare before analysis which layer's closed loop you are drawing); **stop-splitting rule** (split only until the current question can be answered); **Merge–Split Double Check** (see Analyze step two). A broken link = a link broken where the user's phase-sense says "not done yet"; a choke point = the block where "if it doesn't pass, everything breaks."

#### 1.0.5 What the Method Applies To, and What It Does Not Promise

- **Applicable objects**: products, projects, works, features, ideas — anything whose question is "should this be done, is it being done right, should it continue."
- **Inborn gaps** (honest declaration): external constraints (regulation, timing windows) and executor capability (the same idea with a different person should yield a different conclusion) are not in the method's foundations; the gating applicability to methodology-type objects is not established. Fill these in separately when using; record significant findings in the report's "Method Boundaries."
- **Not promised**: all public cases come from known business history — post-hoc induction with no verified track record of ex-ante prediction; this method does not guarantee correct conclusions, only **conclusions that are checkable against evidence and actions that are acceptable as done** — its value is hallucination prevention, not prophecy.

#### 1.0.6 The Final Verdict (choose one of seven)

Double Down / Continue / Complete (actual solution pending verification) / Repair (fatal problems exist) / Retire (already superseded) / Kill (gatekeeping failed or Graveyard confirmed) / Hold (insufficient evidence) — inventing options is forbidden.

### 1.1 The Disciplines You Must Obey

1. **Analyze first, write later**: every conclusion in this report must come from a complete analysis executed under the §1.0 methodology (the B6 standard). Generating a report without having run the analysis = void. If the user has given only a project name and material, first complete the full B6 flow yourself, then enter typesetting.
2. **Simplified Chinese**: filename, body, tables, captions, headers and footers — all in Simplified Chinese (numerals and underscores excepted). Traditional characters are forbidden. (When producing a report in another language, apply the same single-script rule for that language.)
3. **Honesty without makeup**: where conclusions conflict with the project side's expectations, write it as it is; if the verdict is "Kill" or "Hold," write it out plainly — this report's value is letting people see clearly, not making them happy. Evidence labels 【实测】/【推断】/【假设】 ([measured] / [inferred] / [assumed]) stay with the text; where there is no evidence, write "to be verified."
4. **Key answers up front**: the answers humans care about most must all appear on **page 2** (see the five questions in 1.2). Later pages are for those who want to dig; burying key conclusions after page 5 is not allowed.
5. **Filename and time**: the output PDF is named `ProjectName_MultiDimensional_Analysis_HumanReadable_YYYYMMDDHHMM.pdf`; the analysis time is taken live with the `date` command as 12 consecutive digits, never estimated.
6. **No technical-capability judgments from memory (new in B6, same-source discipline as the Assignment document)**: any judgment touching "where current technical capability stands, or whether solutions have strengthened recently" must be verified by live search; when search is impossible, explicitly label it "based on my knowledge cutoff of [date]; human review required" — an AI's knowledge cutoff is an old map; measuring a technology curve with an old map is navigating with an expired map.

### 1.2 Report Structure (in order)

**Page 1 · Cover**:
- Project name (main title) + the subtitle "Multi-dimensional Analysis · Human-Readable Edition";
- Analysis standard: MDPAF B6 (Pain Point Analysis merged in · opportunities have a shelf life · includes the Timing Question) · full edition;
- Analysis time (taken live with `date`) · one line on the object of analysis · the fact provider and the compiler (human / AI, labeled separately);
- If a previous report exists: note its standard and date, and whether this edition is a full re-audit or an incremental revision.

**Page 2 · Key Quick View (a human reading only this page walks away with every decision element)** — five questions, five answers, each one a paragraph giving the conclusion directly; "see below" dangling pointers are forbidden:

| Question | What the answer contains (which analysis output it comes from) |
|---|---|
| **① Is it worth doing?** | The final verdict (one of seven: Double Down / Continue / Complete / Repair / Retire / Kill / Hold) + a one-line reason + whether the Coarse and Fine Gates passed + **Timing (why now: capability just reached it = window just opened / reached long ago yet nobody did it = a reason or a corpse)** |
| **② Who are the competitors?** | Incumbents on the core blocks: direct competitors named one by one + the Folk Workaround (how users make do now) + Graveyard status (did the people who tried die) |
| **③ What do they lack?** | The satisfaction gap of existing solutions (Folk Workaround included): what users complain about, what they endure, the most painful moment while making do; the composition of switching cost |
| **④ What do we have that they don't?** | Our differences from competitors, listed one by one — with a simultaneous **two-way check**: how hard would it be for competitors to copy each difference (replication difficulty) + our moat candidates (if you can't write one, write "none"); if there is nothing competitors lack, write honestly "no differentiators for now" — this is the most important honesty |
| **⑤ What to refine, extend, delete?** | Refinement directions (ROI-ranked + rough cost + acceptance criteria), extension candidates (those that passed the three gates), parts recommended for deletion / deferral — three short lists |

At the top of page 2, one large-type line with the "Final Verdict"; after the five-question table, one line defining the labels ([measured] / [inferred] / [assumed]).

**Page 3 onward · Analysis body** (for those who want depth, organized on the B6 scope axis):
- Dimension 0, Coarse Gate (claimed pain block + evidence);
- Dimension 1, Mapping (long-chain block diagram: may be drawn with HTML/CSS box diagrams or inline SVG, marking choke points, parallel blocks, task anchors);
- Dimension 2, Re-slicing to settle scope (Side-by-Side Reveal table + Coverage Correction + Fine Gate conclusions: full Seven Questions + **the Timing Question** "why now");
- Dimension 3, Measuring (three judgment groups — chain level / object level / core-block level — with per-block labels: opportunity / also-ran / loss-leader / deferred);
- Dimension 4, the ledger (Payment Triangle, revenue, cost, moat, two-way replication check);
- Dimension 5, closing (conclusions + the ranked refinement table: number / action / rough cost / acceptance criteria);
- Growth scan (if the verdict is Double Down or Continue): candidate list + three-gate conclusions.

**Last page · Appendix**:
- Sources and conflict record (the provenance of each [measured] item, listed; where sources disagree, record it as it is);
- Method boundaries (open questions of compliance / timing / executor capability);
- A small glossary (Graveyard check, moat, Payment Triangle, the seven-way verdict, opportunity shelf life, Embedding Position, Timing Question — for readers new to B6).

### 1.3 Layout and Output Requirements

- **HTML → PDF**: first write a self-contained HTML (inline styles, no external resources; diagrams as inline SVG or CSS box diagrams), then convert to PDF with a headless browser (Edge: `--headless --disable-gpu --no-pdf-header-footer --print-to-pdf`); A4 portrait, white background, print-friendly, every page with a header (report name + standard + date) and page number.
- **Page 2 discipline**: the quick view stands on its own page; information density may be high (tables, bold, color blocks), but every conclusion must be complete and readable — a human skipping every other page can still decide on this page.
- **Self-explanatory diagrams**: every diagram carries a legend and a caption; colors that need context to be understood are not used.
- **Post-generation self-check**: with a PDF library (e.g., pypdf), verify the page count and that page 2 contains all five questions; old report files are never overwritten; the new filename carries the new timestamp.
- **Language self-check**: after generation, search the full text for Traditional characters (common ones: 專項 / 報告 / 時間 / 後 / 裡); fix any found to Simplified.

### 1.4 Quality Red Lines (violating any one = redo)

1. Page 2 missing any of the five questions;
2. A conclusion containing evidence absent from the analysis (closing adds no new material);
3. Numbers without evidence carrying no "to be verified" label;
4. The verdict not being one of the seven words (invented vocabulary);
5. Traditional characters remaining;
6. The filename lacking the 12-digit timestamp, or the timestamp being estimated rather than taken live with `date`;
7. An opportunity judgment without "how long it holds / when it gets replicated" (Corollary Three), or a technical-capability judgment that was neither searched nor labeled with the knowledge cutoff.
